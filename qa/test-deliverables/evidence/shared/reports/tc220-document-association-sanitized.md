## 1. Test Objective & Scope

Verify that after an applicant submits:
1. Exactly one submitted applicant/personnel record exists in `tbl_personnel_info`.
2. Accepted synthetic documents have metadata records in `tbl_personnel_documents` linked via foreign key `personnel_id`.
3. The stored file path belongs to that personnel ID (`Uploads/documents/{personnelId}/{fileName}`) and prevents path traversal or cross-crew leakage.
4. Physical file integrity (non-zero size, valid `%PDF` signature).
5. The application-generated protected handler enforces strict 7-role access control.
6. Direct static file access to `~/Uploads/documents/` is unconditionally blocked.

## 3. Protected Handler & Static Access Verification

### A. Live Handler Inspection on Azure Staging
- **Handler URL Definition in Code:** `~/Crew/CrewDocumentHandler.ashx?id={docId}` (generated by `ProfileViewer.aspx.vb`).
- **Live Staging Endpoint Probe:**
  - Request: `GET https://ummi-crew-hdccaegqbke9gwab.southeastasia-01.azurewebsites.net/Crew/CrewDocumentHandler.ashx?id=11`
  - Unauthenticated Response: `HTTP 403 Forbidden` (`You do not have permission to view this directory or page.`).
  - Authenticated Response (Manning Staff): `HTTP 404 Not Found` (`The resource you are looking for has been removed, had its name changed, or is temporarily unavailable.`).
  - **Finding:** The physical file `CrewDocumentHandler.ashx` is missing or not mapped in the deployed Azure staging App Service build `c737536`, whereas `AssessmentAttachmentHandler.ashx` is deployed.

### B. Direct Static File Blocking Verification
- **Request:** `GET https://ummi-crew-hdccaegqbke9gwab.southeastasia-01.azurewebsites.net/Uploads/documents/sample.pdf`
- **Result:** `HTTP 404 Not Found` (Zero document bytes).
- **Configuration Proof:** In `Web.config` (lines 124–136):
  ```xml
  <location path="Uploads/documents">
    <system.web>
      <authorization>
        <deny users="*" />
      </authorization>
    </system.web>
    <system.webServer>
      <handlers>
        <clear />
        <add name="BlockDocumentsDirect" path="*" verb="*" type="System.Web.HttpForbiddenHandler" />
      </handlers>
    </system.webServer>
  </location>
  ```
  IIS intercepts all direct requests to `~/Uploads/documents/` and denies access unconditionally.
